# Implementation Plan: Dashboard Shell & Role-Aware Navigation

**Branch**: `008-dashboard-shell` | **Date**: 2026-04-04 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/008-dashboard-shell/spec.md`

## Summary

Build a persistent app shell wrapping all authenticated dashboard pages. The shell renders a role-filtered sidebar (desktop), icon-only collapsed sidebar (tablet), and bottom navigation (mobile). Role is resolved server-side from Clerk's `orgRole`. Forbidden routes redirect server-side to `/inbox`. RTL layout driven by `dir` on `<html>` with Tailwind logical properties. Built on shadcn/ui `Sidebar` component.

---

## Technical Context

**Language/Version**: TypeScript (strict, no `any`) — Next.js 15 App Router
**Primary Dependencies**: shadcn/ui (Sidebar component), Tailwind CSS v4, Lucide React (icons), Clerk (`auth()` server-side)
**Storage**: None — no new Convex tables; reads Clerk session only
**Testing**: Manual E2E per quickstart.md (25 scenarios across 4 user stories)
**Target Platform**: Web — desktop (≥1024px), tablet (768–1024px), mobile (<768px); iOS Safari safe area required
**Project Type**: UI shell / layout component
**Performance Goals**: Shell renders without layout shift; no client-side role fetch flash
**Constraints**: Role must be resolved server-side (no flash-of-unauthorized-UI); RTL must work without per-component logic
**Scale/Scope**: 3 roles × 4 breakpoints × 2 locales = 24 combinations to validate
