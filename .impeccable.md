## Design Context

### Users
Arabic-speaking SMB owners, admins, and agents in Egypt, Saudi Arabia, and UAE. They use WABDesk as a shared WhatsApp inbox — a daily operational tool, often on desktop. Their context when using auth/onboarding flows is that they're new or returning — they want to get in quickly and start handling customer conversations. They're business-minded, not technical.

### Brand Personality
Confident, Arabic-first, trustworthy. Three words: **Professional, Welcoming, Precise.**
The emotional goal: the user should feel they've joined something well-crafted — not generic SaaS, not a startup toy. The interface should feel like it was designed specifically for them and their market.

### Aesthetic Direction
Apple-inspired refined minimalism. Key tokens already in the codebase:
- **Primary blue**: `#0071E3` (auth) / `#2563eb` (dashboard) — use `#0071E3` for auth/onboarding flows
- **Background**: `#F5F5F7` with subtle radial blue gradient at top
- **Cards**: `bg-white/90 backdrop-blur-xl border border-black/8 rounded-[22px]` — glass-like white cards
- **Shadow**: `0_2px_6px_rgba(0,0,0,0.04),0_10px_30px_rgba(0,0,0,0.08)` — soft layered shadow
- **Fonts**: IBM Plex Sans Arabic for Arabic text, Inter / SF Pro for English
- **Text colors**: `#1D1D1F` (heading), `#6E6E73` (secondary)
- **RTL first**: All layouts must work in RTL by default

Anti-references: Generic dark SaaS (dark backgrounds with neon glow), Slack-style multicolor, Bootstrap-style corporate blue.

### Design Principles
1. **Arabic-first, never bilingual UI** — show one language based on the user's locale cookie; never show both on screen simultaneously
2. **Match the auth visual language** — onboarding and auth-adjacent pages (select-org, verify-email) share the glass card + gradient background aesthetic
3. **Every screen has an exit** — users can always cancel/sign out; no dead ends
4. **Empty states teach** — when there's nothing to show, explain what to do next with warmth, not just a bare button
5. **Surgical precision** — only change what the task requires; no scope creep, no cosmetic "improvements" to unrelated components
